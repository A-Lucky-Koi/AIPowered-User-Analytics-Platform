# 单机架构与扩展

```text
浏览器：Vue 3 页面状态 → ECharts 图表 + 可访问数据表
          ↓ 同源 Cookie + CSRF
HTTP API：鉴权 → 角色 → 渠道范围 → 参数校验 → 审计
          ↓
数据仓储：SQLite players + activity + spend
          ├─ 指标与 Cohort / 漏斗 / LTV / 分群聚合
          ├─ 配置 / 收藏 / 告警状态 / 审计持久化
          └─ 已授权聚合快照 → 内存 SQL 只读沙箱
AI Gateway：保留接口，当前返回 501
```

## 技术设计

分析任务是运营监控、时间变化、渠道比较和批次留存；主路线为仪表盘，使用折线、条形、散点、漏斗和 HTML 热力表。ECharts 使用 Canvas；热力表/指标/数据备选表保留为可访问 HTML。每页同时 1–3 个图表，趋势最长 366 日，避免绘制事件级数据。颜色主序列为紫，辅助为青/蓝；异常使用文字、方向和红色，不能只依赖颜色。

Chart 组件独立负责创建、更新、ResizeObserver 和 dispose，页面切换会销毁实例。关闭动画，并适配 reduced-motion。每图均有可展开数据表和 PNG 导出；关键值直接显示在卡片与表格，不要求悬停。移动端使用折叠菜单、双列 KPI，表格局部横向滚动；键盘弹层有焦点范围和 Escape 关闭。

日期/渠道/设备/区服/注册版本/页面存在 URL 查询串；前进后退会恢复并查询。收藏保存在服务端且按账号隔离。临时悬停、图表数据展开、AI 输入不会写入 URL。SQL 结果在筛选变更时清空，人群预览在规则变化时清空。保留上次成功数据时必须显示错误或筛选未应用标记。

## 更新与成本

数据模式为 T+1/手工导入。打开且可见的页面每 60 秒重新拉取元数据与聚合结果；没有常驻后台调度或真正流式遥测。时间序列限 366 日，导入限 50,000 行，分群限 10,000 人，SQL 快照限表与函数且返回不超过 1,000 行。所有浏览器资源在本地，不依赖运行时 CDN。

SQLite 开启 WAL，有注册日期、渠道维度、活动日期及主键索引。每个 HTTP 请求使用独立连接，明确关闭；鉴权后业务查询开启事务读取一致快照。CSV 所有行校验完再提交，同批错误整体回滚。Python HTTP 线程服务仅作为本地可运行实现，不保证高并发延迟或可靠性 SLA。进一步优化应拆分各页面 API、引入预聚合缓存与后台计算，再通过负载测试制定预算。

## 对应原始分层

| 原设计 | 本地交付 | 生产替换方向 |
| --- | --- | --- |
| Kafka / Flink / Spark | 已清洗日事实 CSV | SDK、采集、流批管线、质量校验 |
| ClickHouse / Doris | SQLite 用户日事实与查询 | 实时/离线 OLAP 适配、分区预聚合 |
| MySQL | SQLite 配置/账号/会话/审计 | 独立关系库、迁移框架 |
| Redis | 无 | 聚合缓存、共享会话、限流 |
| 指标语义层 | data.METRICS + 范围参数 + 三个 SQL 语义表 | 版本化语义服务与字典审批 |
| RBAC + 行权限 | 四种角色 + 单渠道范围 | SSO、多渠道/项目、字段权限、账号生命周期 |
| 异常检测 | 日环比阈值与贡献拆解 | STL / Isolation Forest、回测、可配置业务日历 |
| AI Gateway | 鉴权后的 disabled 路由 | 私有模型适配、工具编排、SSE、问答审计 |
| 推送与调度 | 页面内 60 秒刷新 | 任务调度、企微/邮件、重试与幂等 |

首次交付保持部署成本低和指标可核验，后续应保持 API 的真实数据与权限边界，再迁移计算和存储；不能仅更换界面标签就宣称已接入生产能力。
